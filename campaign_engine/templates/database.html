How the design reaches 3NF

Unnormalised. One wide sheet per post: post_id, brand, platform, followers, campaign, content_type, likes, …, comment_texts = "Price please?; Delivery kitne din?", comment_topics = "Price inquiry; Delivery inquiry", source_name, provenance, collected_on. Several comments are crammed into one cell, so the data is hard to query or count.
1NF – atomic values, no repeating groups. The comment list moves to its own comment table: one row per comment (comment_id PK, post_id FK). Every column now holds a single value.
2NF – no partial dependencies. If comment rows carried the post's brand, platform or likes, those would depend only on post_id, not on the whole key. They stay in post; comment keeps only what describes the comment.
3NF – no transitive dependencies.
  • followers depends on (brand, platform), not on the post → new table account.
  • Names such as campaign, content type, category, language, sentiment, intent → lookup tables referenced by ID, so each value is stored once and typos cannot creep in.
  • provenance, source_url, collected_on depend on the source, not the post → data_source (keeps real and simulated data separate).
  • theme depends on the topic → stored in topic.
  • Engagement rate, totals and peer groups are derived, so they are computed in queries and never stored.
