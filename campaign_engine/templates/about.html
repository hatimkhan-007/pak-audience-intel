The lawn-suit dataset is simulated; the YouTube comments are real. In the simulated data, brand names are fictional and none of the figures are real measurements. The real YouTube comments (Project 2 export) are stored as observed and kept out of the lawn-suit analysis because they come from a non-fashion video; see the YouTube page. It exists so the full engine can be demonstrated; it was designed with realistic patterns (e.g. one brand with delivery problems, one with discount hunters) so the analysis has structure to discover. Real public data can be loaded with python manage.py import and is stored with provenance = observed, so real and simulated records are never mixed up. Always respect each platform's terms and only use data you are permitted to collect.

Pipeline

  1. Load posts (Table A) and comments (Table B) into the normalised database.
  2. Understand each comment: language (English / Roman Urdu / Urdu), topic, sentiment and purchase intent with transparent keyword rules built for code-mixed text. Agreement with the generator's hidden labels on the simulated data: {{ '%.1f'|format((meta.get('topic_accuracy_vs_simulated_labels','0')|float)*100) }}%.
  3. Cluster comments: words from all three languages are mapped to shared concepts (e.g. “قیمت”, “price”, “kitne ka”), vectorised with TF-IDF, reduced with SVD and grouped by K-Means. k = {{ meta.get('k') }} was chosen by silhouette score. Each cluster is named by its dominant topic.
  4. Find unusual posts: robust z-scores against comparable posts (brand + platform + format) on engagement, comment rate, shares and complaint share, then an Isolation Forest to combine them.
  5. Recommend: rule-based, each rule quotes the numbers that triggered it.

Limitations to keep in mind

  • Engagement rate uses followers as the denominator; views are only available for some formats and platforms.
  • Only a sample of each post's comments is stored (3-25), so per-post comment shares are noisy; the engine requires at least 3 matching comments before treating a pattern as meaningful.
  • Rule-based topic detection will miss sarcasm and new slang. Segment names come from the dominant topic and each card shows how pure that cluster is.
  • Anomalies are statistical, not verdicts. Investigate before acting.
  • Segments describe correlation in text; test recommendations with A/B experiments before committing budget.

Suggested real data sources

  • Public posts from Pakistani lawn brands, collected only through permitted methods and each platform's terms.
  • The 2026 study on Pakistani fashion-brand sentiment (10,602 observations, 17 brands) — check its availability and reuse terms first.
  • Open Data Pakistan e-commerce orders (transaction context, not comments) and the Pakistani fashion catalogue on Hugging Face (75 product records with PKR prices).
